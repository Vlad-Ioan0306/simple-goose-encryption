# Security Policy

## This software is not secure

This project is an **educational demo only**. The encryption used is a toy-grade
XOR stream cipher seeded by a `u16` (65,536 possible seeds). It provides no
confidentiality, integrity, or authenticity guarantees.

**Do not use this to encrypt anything you need to keep private.**

## Known limitations

- The keystream is generated by a simple xorshift-like recurrence over a 64-bit
  state. It is linear and trivially breakable with known plaintext.
- The seed space is only 16 bits when auto-generated.
- The seed is stored in plaintext in `.seed` in the working directory.
- No authentication (MAC/signature) — ciphertext can be modified undetected.
- No key derivation, salting, or stretching.

## Intended use

Learning Goose systems programming: byte slices, CLI args, file I/O, base64
encoding/decoding, and project structure. Roadmap step 3 explores C interop via
`extern fn`, but even a C-backed stream cipher here would remain demo-grade.

## Reporting

There is no security response process for this project because it is not a
security product. If you find a bug, feel free to open an issue, but do not
expect patches for cryptographic weaknesses — they will not be fixed.
