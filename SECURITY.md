# Security Policy

## This software is not secure

This project is an **educational demo only**. The encryption used is a toy-grade
XOR stream cipher seeded by two `u64` values (128-bit seed space) with a per-message
`u64` nonce. A single `u64` `--key` may be supplied for both states. It provides no
confidentiality, integrity, or authenticity guarantees against a determined attacker.

**Do not use this to encrypt anything you need to keep private.**

## Known limitations

- The keystream is generated by a simple xorshift-like recurrence over two 64-bit
  states. It is linear and trivially breakable with known plaintext.
- The seed space is 128 bits (two u64 values), but the construction itself is weak.
- The seed pair is stored in plaintext in `.seed` in the working directory.
- The nonce is prepended to the ciphertext in the clear. It must never be reused with
  the same seed pair; nonce reuse in a stream cipher lets an attacker cancel the
  keystream by XORing two ciphertexts together.
- No authentication (MAC/signature) — ciphertext can be modified undetected.
- No key derivation, salting, or stretching.
- Files are processed in 64 KB chunks; each chunk is xored with the same keystream
  continuation, so chunk boundaries do not reset the cipher state.

## Intended use

Learning Goose systems programming: byte slices, CLI args, file I/O, base64
encoding/decoding, and project structure.

## Reporting

There is no security response process for this project because it is not a
security product. If you find a bug, feel free to open an issue, but do not
expect patches for cryptographic weaknesses — they will not be fixed.
